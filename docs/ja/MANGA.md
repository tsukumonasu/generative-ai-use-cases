# 漫画生成

## 何をする機能か

シナリオや指示の文章、または過去のチャットの会話から、コマ割り・フキダシ・セリフまで入った漫画を数ページ分まとめて生成します。メニューの「漫画生成」(`/manga`) から使います。

生成は 3 段階で進みます。

1. **構成**: 「構成を考える AI モデル」(チャットと同じ Bedrock のモデル) が、タイトル・画風・登場人物の見た目・各ページのコマ割りとセリフを決めます。
2. **キャラクター設定画**: 登場人物を並べた設定画を 1 枚生成します (ON / OFF を選べます)。
3. **各ページ**: 1 ページを 1 枚の画像として順に生成します。コマの枠・フキダシ・文字もすべて画像生成モデルが描きます。

登場人物の見た目がページごとに変わらないよう、各ページの生成には「キャラクター設定画」と「直前のページ」を参照画像として渡します。

## 使い方

### 入力

| 項目                  | 内容                                                                                                                                    |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| シナリオ・指示        | 物語のあらすじ、登場人物の設定、オチの方向性、テイストの希望などを自由に書きます                                                        |
| チャット履歴を選択    | 過去のチャットの会話をシナリオの元ネタにします。シナリオ欄と併用できます (長い会話は末尾の 10,000 文字を使います)                       |
| 登場人物の写真 (任意) | 写真の人物をキャラクターとして登場させます。最大 6 枚 (PNG / JPEG / WebP)。写真ごとに名前が必須で、役割や性格の補足も書けます           |
| テイスト              | 少年漫画、少女漫画、青年漫画・劇画、4 コマ・ギャグ、アニメ風 (カラー)、アメコミ風、デフォルメ・ちび、水彩・絵本風。追加の指定も書けます |
| 読む方向              | 右から左 (日本の漫画、既定) / 左から右 (アメコミ)                                                                                       |
| ページ数              | 自動 (AI がシナリオから最大 16 ページの範囲で決める、既定) / 1〜16 ページから選択。1 ページのコマは最大 8 個です                        |
| キャラクター設定画    | 既定は ON。画像 1 枚分のコストが増えますが、見た目が安定します。写真を使うときは ON がおすすめです                                      |

### モデルの選択

入力欄の下で 2 つのモデルを選びます。どちらもブラウザごとに前回の選択を覚えています。

- **作画モデル**: 「画像生成・編集」と同じ一覧 (Gemini と GPT Image) から選びます。選んだモデルによって設定項目が変わります。
  - Gemini: ページのアスペクト比 (既定 3:4) と解像度 (既定 1K)
  - GPT Image: ページサイズ (既定 1024x1536) と品質 (既定 低)
- **構成を考える AI モデル**: 写真を付けたときは、写真を読み取るため画像に対応したモデルだけが選べます。

既定の解像度・品質は、PDF のサイズと生成時間を抑えるため最小にしています。セリフを読みやすくしたいときは Gemini の 2K 以上、または GPT Image の品質を上げてください (ファイルサイズと時間は増えます)。

### 生成後

- **このページを再生成**: 1 ページだけ描き直します。
- **ダウンロード**: ページごとに画像を保存します。
- **PDF に保存**: 全ページを 1 つの PDF にまとめます (1 ページに 1 画像)。
- **チャット履歴で表示**: 1 回の生成は 1 つのチャット (ユースケース `/manga`) に記録されます。履歴には、モデルに渡した長い指示文ではなく「タイトル P3: 要約」のような短い説明が残ります。

結果は別のページに移動しても残ります。「クリア」で消えます。

## 写真の扱い

- 写真はブラウザ内で長辺 1024px の JPEG に縮小してから送ります。
- 構成の段階では、モデルが写真を見て登場人物の見た目を文章にします。
- 作画の段階では、写真を**キャラクター設定画の生成に**参照画像として渡します。各ページは設定画を通して顔立ちを引き継ぎます。設定画を OFF にした場合は、写真を各ページに直接渡します。
- モデルには「写真は写真であり、貼り付けたりなぞったりせず、似せて描き直す」ように指示しています。
- 写真は GenU のファイル用 S3 バケットに保存され、他のアップロードファイルと同じ扱いになります。**本人の了承を得た写真だけを使ってください。**

## 有効化

専用の設定はありません。**GPT Image か Gemini のどちらかが有効なら**メニューに表示されます ([設定方法](./DEPLOY_GEMINI_GPT_IMAGE.md))。作画モデルの一覧も、その設定 (`openAiImageModel(s)` / `geminiImageModel(s)`) から決まります。

新しい Lambda や AWS リソースはありません。既存の `InvokeGemini` / `InvokeGptImage` の Lambda を 1 ページにつき 1 回呼び出します。

## 制約と注意点

- **時間**: ページ数に応じて数分〜十数分かかります。生成はブラウザが順に進めるので、**生成中はタブを閉じないでください** (閉じるとそこで止まります。生成済みのページはチャット履歴に残ります)。
- **コスト**: 構成の 1 回 + 設定画 1 枚 + ページ数分の画像生成です。16 ページなら画像 17 枚分です。
- **文字**: セリフも画像生成モデルが描くため、長いセリフや細かい文字は崩れることがあります。解像度を上げるか、そのページを再生成してください。
- **見た目のずれ**: 設定画と直前のページを参照しても、ページが進むと服装や髪型が少し変わることがあります。
- **GPT Image**: 参照画像を付けるページは編集用の API で生成します。
- **履歴から開いた場合**: 履歴の一覧から開くと通常のチャット画面 (`/chat/:chatId`) になり、画像は見られますが、続きの生成や再生成はできません。
